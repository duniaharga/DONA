# SEO, Accessibility and Lighthouse Optimizer

## Completion workflow
After completing a page, run the project-local `media-library-optimizer` first, then this skill, then `a11y-compliance-auditor` for detailed manual accessibility verification, and finally `human-website-qa`. Reuse the media report rather than repeating its inventory. Keep this pass on the completed page and shared components it uses; a page audit does not authorize a site redesign, new plugins, external publishing, analytics enrollment, or global indexing changes.

Aim for **100/100 in all four Lighthouse categories**. Measure actual scores; never guarantee 100, invent a score, equate it with search ranking or complete accessibility, or break functionality to achieve it. Distinguish scored audits, diagnostics, and manual checks. Read [audit workflow](references/page-completion-audit.md) when running the pass.

## Inspect and correct
1. Read project context and inspect the saved native Builder layout, actual rendered page, active SEO plugin, language, audience, and intended URL. Preserve completed content and design. Use verified facts; do not invent brand history, offers, certifications, FAQs, ratings, or keyword volumes.
2. Confirm one clear H1, meaningful heading order, semantic regions, descriptive page title and meta description, canonical URL, Open Graph image/text, correct language, valid crawlable links and appropriate structured data. Use the existing Rank Math configuration when available; avoid duplicate schema. Check sitemap inclusion where applicable. Preserve intentional local/staging/Coming-soon noindex settings and identify production-dependent findings separately.
3. Give **every actionable link, button, icon control, input and dialog an appropriate accessible name**. Prefer visible descriptive text, native labels, and `aria-labelledby`; add `aria-label` for otherwise unnamed/ambiguous controls. Do not add redundant labels to every text link or override a good visible name. Include the visible wording in the accessible name. Use anchors for destinations, buttons for actions, keyboard access, visible focus, correct expanded/pressed states and focus return for dialogs. Verify contrast, text zoom, reduced-motion behavior and touch targets.
4. Confirm image alternatives in context using the media report: informative descriptions, functional purpose for icon links, empty alt for decorative/duplicate images. Check the actual rendered attributes, not only attachment metadata. Add meaningful captions only where they clarify the image; do not create repetitive captions on product grids or expose decorative images to assistive technology.
5. Run Lighthouse on mobile and desktop using an available authorized runner or Chrome interface. Record tool/browser version, URL, environment, timestamp, authentication state, viewport/preset and throttling. Prefer a guest storefront baseline; do not sign out a user's active session just to obtain it. If tools/site access block a run, report it as unverified rather than replacing it with a DOM check.
6. Address failures in impact order: response/server errors and broken resources, missing names/labels, indexability appropriate to the environment, render-blocking work, LCP media, excessive JS/CSS, layout shifts, fonts, console errors, and unsafe resource loading. Keep WooCommerce variations, account, cart, checkout, media, consent and YOOtheme editability working. Do not lazy-load the LCP image or preload every image. Avoid global CSS/JS removal solely because it was unused on one page.
7. Rerun affected measurements after fixes under comparable conditions. Explain external constraints such as Studio server latency, third-party scripts, local HTTP or unavailable production headers. Keep genuine manual accessibility checks in the final report even if Lighthouse reports 100. Stop when checks pass or the remaining items have specific evidence and a stated blocker; do not loop unchanged tests indefinitely.

## Deliverables
Save a concise page report in `project-context/audits/<page-slug>/` with before/after scores for each measured category/device, Lighthouse JSON/HTML artifacts when supported, applied SEO/accessibility changes, media-report reference, manual checks, regressions, and remaining blockers. Use pass/fail/unverified/environment-dependent labels. Final reply reports actual results and material unfinished work; never claim all parameters are 100 without supporting reports.
