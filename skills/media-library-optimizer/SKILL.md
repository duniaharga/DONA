# Media Library Optimizer

## Scope and workflow
Run when a page is finished or substantially revised, before the SEO/Lighthouse pass. Start with that page's images, videos, posters, backgrounds and responsive variants. Reuse the project's media folders and existing optimization work. Read [reference audit and safe changes](references/media-reference-audit.md) before renaming or removing existing files.

1. Inventory media used by the page and record attachment ID, actual file/URL, dimensions, bytes, type, role, current metadata and reference locations. Inspect the actual image before describing it. Detect existing matching assets before importing duplicates.
2. Make metadata useful and accurate: short descriptive attachment titles; contextual alt text for informative images; action/destination for functional images; empty alt for decorative or redundant images. Add descriptions that identify visible content without invented claims. Add captions only when useful to the reader or requested by the design. Alt text, title, caption and description serve different purposes; do not duplicate keyword strings across them.
3. Use concise, lowercase, hyphenated descriptive filenames for new imports, preserving correct extensions and meaningful product/color/view information. For existing files, distinguish attachment-title changes from actual filename/URL changes. Rename only when references and WordPress metadata can be migrated safely and verified; if not, keep the working URL and record the proposed rename. Avoid forced renames of already suitable filenames.
4. Optimize delivery without degrading the accepted design: correct image sizes/srcset, dimensions, compression or modern formats where supported, appropriate image loading, video `preload`/poster behavior, and no eager loading of inactive color media. Retain originals or a rollback copy where transformations occur. Keep SVG/vector assets intact and use an appropriate image tool for raster edits.
5. Organize attachment IDs into existing native media folders by purpose; do not install a folder plugin. Maintain product/color relationships and existing selections.
6. Identify unused/duplicate candidates through a **sitewide read-only reference audit**, even when the completion pass concerns one page. `post_parent=0`, a filename mismatch, age, or lack of a reference on this page is not evidence of non-use. Shared media, lower galleries, all product color variations, responsive derivatives and hidden interactive states count as use. Classify each candidate as used, confirmed unused, or uncertain with evidence.
7. Apply authorized cleanup reversibly after verifying all references. Prefer supported WordPress media trash when available, or retain candidates in place with a cleanup manifest when it is not. Store an authorized rollback copy and reference/metadata manifest before removals or URL migrations. Do not delete originals permanently, remove files in bulk, or enable new trash/security settings without the applicable authorization. Recheck references immediately before a destructive step; stop that step if the inventory changed or evidence is incomplete. Continue unrelated optimizations.
8. Verify attachment files, generated sizes, saved Builder/ACF references and actual page requests after changes. Check affected shared pages or variation states when an asset was shared. Pass the report to `seo-geo-optimizer`, which measures page-level results; do not claim storage cleanup alone raised Lighthouse scores.

## Deliverables
Save `project-context/audits/<page-slug>/media-report.json` (or a concise equivalent) with metadata changes, context-specific alt overrides, retained/generated files and sizes, folder assignments, old/new paths if renamed, reference evidence, confirmed-unused/uncertain candidates, cleanup action and rollback location. Report exactly what was optimized, renamed, trashed, retained or left unresolved. Do not claim a file was removed when it was only proposed for removal.
